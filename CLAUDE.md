# GyverTwink — сведения для работы с проектом

Гирлянда на адресных светодиодах (WS2812) и ESP8266, управление по WiFi (UDP) из Android-приложения.
Главная особенность — автокалибровка по камере: для каждого светодиода сохраняются координаты x/y,
эффекты строятся по геометрии, а не по номеру в ленте. Автор оригинала — AlexGyver, лицензия MIT.

Долговременная память проекта лежит в `docs/`: **читай перед началом работы**.
- `docs/ROADMAP.md` — дорожная карта (статус пунктов, приоритеты).
- `docs/DECISIONS.md` — журнал принятых решений (что решили и почему).
- `docs/UDP_protocol.txt` — протокол обмена.

## Структура
| Путь | Что |
|---|---|
| `firmware/GyverTwink_v1.2/` | Прошивка ESP8266 (Arduino, несколько `.ino`-вкладок) |
| `processing/GyverTwink/` | Исходники Android-приложения (Processing) |
| GitHub Releases | Собранное приложение (APK); в дереве репозитория бинарников нет. Новый APK собирается вручную и прикладывается к релизу |
| `libraries/` | Скопированные библиотеки: EncButton 1.x, EEManager, SimplePortal (FastLED подтягивается PlatformIO из реестра, версия в `platformio.ini`) |
| `platformio.ini`, `.github/workflows/build.yml` | Сборка и CI |
| `tests/` | Хост-тесты прошивки (заглушки Arduino/FastLED/WebServer, ASan/UBSan), стенд протокола, e2e веб-интерфейса |
| `web/`, `tools/gen_web.py` | Исходники веб-интерфейса (HTML/CSS/JS без зависимостей) и сборка в `web_page.h` |

## Прошивка: карта файлов
- `GyverTwink_v1.2.ino` — настройки (`LED_MAX=500`, пины), структуры EEPROM, `setup`/`loop`.
- `parsing.ino` — разбор UDP (порт 8888), все команды протокола.
- `effects.ino` — отрисовка: 11 палитр × 2 режима (градиент / шум Перлина) = 22 эффекта (`ACTIVE_PALETTES`) и 6 новых с номерами 22–27 (звёзды, бегущие огни, огонь, дыхание, волны по высоте / от центра; `EXT_EFFECTS`). Всего `EFFECT_COUNT`. Настройки эффекта по номеру — `effAt(n)` (types.h): у 0–21 это `effs[]`, у новых `effsX[]`; не обращайся к `effs[n]` напрямую.
- `switcher.ino` — смена эффектов (по кругу / случайно, только «избранные»).
- `button.ino`, `startup.ino`, `faders.ino` — кнопка, WiFi-портал/AP/STA, индикация.
  Пароль точки: в режиме AP с пустым `portalCfg.SSID` поле `portalCfg.pass` = пароль точки (задаётся в портале), иначе `GT_AP_PASS`. Размер `PortalCfg` не менять (первый блок EEPROM).
- EEPROM (2048 байт, занято около 1,2 КБ): WiFi, `cfg`, `effs[22]`, `mm` (границы), `xy[500][2]` (координаты, `byte`), `pwr` (лимит тока), `effsX[6]` (настройки новых эффектов), `sched` (расписание), `guard` (токен).
  **Новые блоки добавлять только в конец** и не менять размеры существующих: иначе сдвинутся адреса и калибровка сбросится.
- `ota.ino` — окно обновления по WiFi (открывают 3 нажатия кнопки; обработчики `/update` в `web.ino`); образ должен быть меньше 900 КБ (проверяет CI).
- `coords.ino` — координаты и границы карты, подсветка светодиода; `scenes.ino` — сцены в LittleFS; `vcalib.ino` — серия для калибровки по видео. Разбор видео - `web/calib.js` (чистые функции, `node --test web/test`).
- `settings.ino` — изменение настроек (общее для UDP и веба: `setPower`, `setBright`, ...); `web.ino` — веб-интерфейс и JSON API (`docs/WEB_API.md`); `web_page.h` — **сгенерированный** файл, править `web/` и запускать `python3 tools/gen_web.py`.
- `power.ino` — ограничение тока (`limitedBright()`), использовать вместо прямого `showLeds(bri)`.
- `guard.ino` — защита токеном (необязательная): проверка заголовка `X-GT-Token`, ограничение подбора по адресам, закрытие UDP-записи (`guard.udpOpen`), блок EEPROM `guard`. **Любой новый API-маршрут веба обязан вызывать `webAuth()` (GET) или `webAllowed()` (POST)** — иначе он обойдёт токен; открыты только `GET /` и `GET /api/auth`. Менять токен можно только при открытом окне (`otaOpen()`).
- `schedule.ino` — расписание (включение/выключение по времени, закату, рассвету): время из NTP или со страницы (`POST /api/time`), события срабатывают раз в минуту, блок EEPROM `sched`. Время и NTP в коде идут через макросы `GT_NOW`/`GT_SET_TIME`/`GT_NTP_BEGIN`, которые тесты подменяют (`tests/host_env.h`).

## Сборка
```
pip install platformio
pio run -e d1_mini          # также nodemcuv2 (оба на ядре 2.7.x) и d1_mini_core3 (ядро 3.x, только проверка сборки)
```
CI (GitHub Actions) собирает все три окружения на PR и push в `main`. Сеть в сессиях Claude Code ограничена:
`downloads.arduino.cc`, `arduino.esp8266.com` и GitHub-релизы блокируются, поэтому локально
платформу ESP8266 не скачать — полную проверку сборки даёт CI. Хост-тесты логики (parsing, switcher, power, effects) — `make -C tests` (нужен только g++, работает и в песочнице), см. `tests/README.md`; **запускай перед пушем изменений прошивки**. Стенд протокола (Python-клиент с ACK против настоящего кода прошивки, потери пакетов): `make -C tests stand` (нужен ещё `python3`); при изменении `ack.pde` правь и `tests/protocol_stand.py`.

## Правила и подводные камни
- Протокол — **вход из сети без аутентификации**: любое значение из пакета валидировать
  (индексы, `ledAm ≤ LED_MAX`, номер эффекта `< EFFECT_COUNT`, длина пакета). Не вводить новых `while(true)` без выхода.
- **Типы (struct) в сигнатурах функций `.ino` объявляй только в `types.h`**: Arduino/PlatformIO вставляет прототипы функций в начало скетча, до вкладок, и тип из другой вкладки там неизвестен (ошибка `'X' does not name a type`). Хост-тесты этого не воспроизводят - ловит только сборка в CI.
- Структуры EEPROM лежат в `firmware/.../types.h` (его же используют тесты). Новый код протокола — вместе с тестом в `tests/test_firmware.cpp`.
- Любой POST веб-API требует заголовок `X-Requested-With: GyverTwink`, значения проверяются строго (`400`, ничего не применяется). Изменил `web/` — запусти `python3 tools/gen_web.py` и закоммить `web_page.h`.
- Менять протокол можно только вместе с приложением (`processing/.../parsing.pde`, `UI.pde`) и `docs/UDP_protocol.txt`.
- Координаты хранятся как `byte` (сетка 256×256); `mm.h` может быть 0.
- `delay(myIP[3]*2)` в ответе на поиск — намеренная задержка против одновременных ответов.
- Вывод на WS2812 блокирует прерывания (~30 мкс/светодиод): тяжёлые операции рядом с `show` учитывать.
- Стиль: комментарии на русском, как в окружающем коде; отступ 2 пробела; без лишних абстракций.
- Библиотеки в `libraries/` не править без необходимости (вендорные копии). Правки: в `EEManager::begin` адрес расширен до `uint16_t`; в `SimplePortal` форма «Access Point» с паролем. Поэтому их нельзя просто заменить версиями из реестра.

## Веб-интерфейс: как работать
- Исходники — `web/` (HTML/CSS/JS без зависимостей), `web_page.h` генерируется `python3 tools/gen_web.py` и коммитится; CI сверяет их (`--check`).
- Обработчики — `web.ino` (тонкий слой над `settings.ino`, `scenes.ino`, `coords.ino`, `vcalib.ino`, `ota.ino`), описание — `docs/WEB_API.md`. Любой POST требует `X-Requested-With: GyverTwink`, значения проверяются строго и применяются «всё или ничего».
- Проверка: `make -C tests` (логика и обработчики), `node --test web/test/...` (чистые функции страницы), `node tests/web/ui_test.mjs ./tests/gt_host` (e2e, нужны Playwright, ffmpeg, numpy). Страницу можно смотреть вживую против кода прошивки на ПК (`tests/README.md`).
- Новая функция веба = обработчик + тест обработчика + проверка в e2e + строка в `docs/WEB_API.md`. Размер прошивки ограничен 900 КБ (OTA), буферы ответов небольшие (стек ESP8266 мал).

## Процесс
- Работа ведётся в отдельной ветке, слияние в `main` через PR; PR создаётся только по просьбе владельца.
- Коммиты — осмысленные, на английском или русском; перед пушем CI должен быть зелёным.
- Любое значимое решение фиксировать в `docs/DECISIONS.md`, статус работ — в `docs/ROADMAP.md`.
