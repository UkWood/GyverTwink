# Хост-тесты прошивки

Запуск: `make -C tests` (нужен только `g++`, без PlatformIO и без железа). Сборка идёт с AddressSanitizer и UBSan:
выход за границы массива, деление на ноль и подобное роняют тест.

## Как это устроено
Тесты собирают **настоящий код прошивки** — `parsing.ino`, `switcher.ino`, `power.ino`, `effects.ino` — как один файл вместе
с заглушками `host_stubs.h` (Arduino, WiFiUDP, FastLED, EEManager). Структуры EEPROM берутся из `firmware/.../types.h`,
тот же файл подключает сама прошивка, поэтому расхождения быть не может.

- `host_stubs.h` — управляемое время (`fakeMillis()`), UDP с очередью входящих/исходящих пакетов, запись вызовов `showLeds`,
  модель мощности FastLED 3.4.0 (скопирована из `power_mgt.cpp`).
- `minitest.h` — минимальный каркас (`TEST`, `CHECK`, `CHECK_EQ`).
- `test_firmware.cpp` — сами тесты.

## Веб-интерфейс
- Обработчики `web.ino` проверяются в тех же юнит-тестах (`test_web_cases.h`): заглушка `ESP8266WebServer` умеет выполнять запрос без сети (`test()`).
- `node tests/web/ui_test.mjs ./tests/gt_host` — e2e: `gt_host` с настоящим кодом прошивки (порт веба из переменной `GT_WEB_PORT`) и страница в настоящем Chromium (Playwright,
  `npm install --prefix tests/web`). Тест проверяет и интерфейс, и то, что реально изменилось в прошивке (строки `STATE` на stdout), и что изменения по UDP видны на странице.

Сцены: `test_scene_cases.h` (очистка имени, обход UTF-8, повреждённый файл, сбой записи, перезагрузка), в e2e - сохранение, применение,
перезапись, удаление и **перезапуск хост-сервера с тем же «флешем»** (`GT_FS_DIR`): сцены должны пережить перезагрузку.

Схема «спираль» (чистая функция страницы): `node --test web/test/spiral.test.mjs` (остаток до S образует верхний ряд, каждый ряд центрирован и идёт слева направо, одинаковый шаг во всех рядах, конус сужается, нижний ряд с наибольшим Y, пропорции и отступы в поле 0..255, крайние случаи, ошибки ввода); в e2e - ввод рядов, подсказка, построение, отмена, сохранение и проверка расположения точек, записанных на «гирлянду».

Редактор координат: `test_coords_cases.h` (формат, пересчёт границ, 11 видов некорректных запросов без изменений, подсветка и её автоотключение), в e2e - загрузка карты, выбор светодиода
(на «гирлянде» горит именно он), перетаскивание мышью, отмена, сохранение, защита от смены числа светодиодов. Чистые функции страницы: `node --test web/test/geometry.test.mjs`.

Новые эффекты (22-27): рендер внутри ledAm и без падений на карте нулевого размера и крайних настройках (ASan/UBSan), огонь жарче снизу, звёзды гаснут и плотность зависит от масштаба,
плавный переход от обычного эффекта, настройки в отдельном блоке (`effsX`, UDP и веб), попадание в автосмену только при «избранном», сцены (формат v2) и миграция файла v1 из прошивки 1.3.

Защита токеном: `test_guard_cases.h` (допустимость и сравнение токена, каждый маршрут API с токеном, без него и с неверным, страница и статус открыты, заголовок страницы проверяется раньше токена, блокировка подбора по адресам: срок, сброс успехом, запрос без токена не считается, вытеснение таблицы, смена и снятие токена только при открытом окне,
всё или ничего, закрытие UDP-записи: запросы работают, запись и ACK-статус 3, прошивка по `/update` без токена). Заглушка сервера отдаёт только заказанные заголовки и адрес клиента. В e2e: вход, неверный и устаревший токен, блокировка, закрытие UDP, снятие защиты.

Расписание: `test_sched_cases.h` (календарь туда и обратно для всех дней 1970–2100, рассвет и закат пяти городов против справочных значений с допуском 6 минут, полярный день и ночь,
события по секундам: один раз в свою минуту, дни недели, ручное изменение не «держится» расписанием, нет повтора после скачка времени, нет событий без времени или при выключенном расписании,
события по закату со смещением, включение сильнее выключения, пропуск во время калибровки; API со строгой проверкой и «всё или ничего», ограничение размера ответа). Время подменяется макросами `GT_NOW` и др. (`host_env.h`).
В e2e: вкладка «Расписание» (синхронизация времени, настройка со страницы, ошибки ввода, срабатывание по часам гирлянды: часы переставляются на несколько секунд до события). Чистые функции страницы: `web/test/schedule.test.mjs`.

Калибровка по видео: `test_vcalib_cases.h` (расписание кадров с проверкой моментов, ограниченный ток маркера, лимит тока, остановка, API), `node --test web/test/calib.test.mjs`
(разбор синтетических кадров), в e2e - **настоящее видео** (`tests/web/make_calib_video.py`: numpy + ffmpeg, VP8) разбирается страницей в Chromium: найденные светодиоды совпадают с настоящими,
невидимые помечены как оценённые, видео без вспышки даёт понятную ошибку, разбор можно отменить. Нужны `ffmpeg` и `numpy` (в CI ставятся через `pip install numpy imageio-ffmpeg`, без apt).

OTA и кнопка: `test_ota_cases.h` (закрытое окно, отсчёт и закрытие по времени, успех с побайтовой проверкой и перезагрузкой через 0,8 с, заголовок страницы, неверный образ/нет места/сбой записи/обрыв загрузки и повтор после неудачи,
три нажатия кнопки; заодно покрыты одно/два нажатия и удержание яркости). В e2e настоящий multipart-запрос из Chromium: хост-сервер получает файл побайтно, «перезагружается» (`REBOOT`), страница дожидается его возвращения.
Хост-сервер принимает команды по stdin: `BUTTON1|2|3` - нажатия кнопки.

## Смотреть страницу вживую
`make -C tests gt_host && GT_WEB_PORT=8080 GT_FS_DIR=/tmp/gtfs tests/gt_host 9999` (каталог `GT_FS_DIR` создай заранее) запускает настоящий код прошивки на ПК: страница на `http://127.0.0.1:8080`, UDP на 9999,
сцены сохраняются в `GT_FS_DIR`. Кнопка: в терминале, где запущен `gt_host`, введи `BUTTON1`, `BUTTON2` или `BUTTON3` и Enter (три нажатия открывают окно обновления прошивки).

## Стенд протокола (`make -C tests stand`)
Второй уровень: тот же настоящий код прошивки собирается как сервер `gt_host`, который слушает UDP на 127.0.0.1
(`host_server.cpp`, сокетная версия `WiFiUDP` в `host_stubs.h`). Python-скрипт `protocol_stand.py` ставит между собой и сервером
прокси, теряющий пакеты (30% в каждую сторону), и гоняет клиента, повторяющего алгоритм приложения (`processing/.../ack.pde`):
рукопожатие `{5}`, очередь по одной команде, повторы с тем же `seq`, слияние значений ползунка. Проверяется, что команда
выполнилась не больше одного раза (и ровно один раз, если клиент не сдался), а старые клиенты работают без изменений.
Клиент в скрипте — **порт** `ack.pde`, а не само приложение: изменив `ack.pde`, правь и `protocol_stand.py`.

## Что покрыто (юнит-тесты)
Старые клиенты и «антидребезг», разбор мусора и огромных пакетов, запросы `{0}`/`{1}`/`{4,0}`/`{5}`/`{7}`, ограничение `ledAm`,
проверка индексов при калибровке и расчёт границ, ACK (сдвиг аргументов, повторы с тем же seq, статусы, пропуск «антидребезга»),
смена эффектов (нет избранных, обход по кругу, случайный выбор), ограничение тока, эффекты при `mm.h == 0`.

## Что НЕ покрыто
`startup.ino` (WiFi, портал), `button.ino`, `faders.ino`, главный `loop()`, реальная модель мощности на ленте, приложение (Processing).

## Правила
- `seq` в ACK-тестах не должен повторяться между тестами (прошивка хранит последний в статической переменной) — используй `newSeq()`.
- Новый код с логикой протокола добавляй вместе с тестом; новая багфикс-проверка — сначала тест, который падает без исправления.
