# Дорожная карта GyverTwink

**Статус документа: v1 — УТВЕРЖДЕНА владельцем 2026-10-19.**
Обновляется по мере работы. Статусы: ⬜ не начато · 🟡 в работе · ✅ готово · ❌ отклонено.

## Принципы
1. Сначала надёжность и проверяемость, потом новые функции.
2. Протокол только расширяется: старые команды и Android-приложение продолжают работать (ACK, токен — опциональны).
3. Каждый этап — отдельный PR с зелёным CI.

## Этап 0. Надёжность прошивки
- ✅ Валидация UDP-входа, защита от зависания `switchEff`, деления на ноль (PR #1)
- ✅ PlatformIO + CI-сборка (PR #1)
- ✅ ACK на команды записи: прошивка (PR #3) и исходники приложения v1.8 (`processing/.../ack.pde`); **APK не пересобран**, проверка на железе — за владельцем
- ✅ Ограничение тока: прошивка готова (`power.ino`, команды `{2,9,...}` и `{7}`), по умолчанию выключено; поле ввода лимита в приложении v1.9 (показывается, если прошивка ответила на `{7}`)
- ✅ Пароль точки AP задаётся пользователем в портале настройки (Access Point + пароль 8–31 символ); пароль по умолчанию остаётся только для старых установок и выхода из портала без выбора

- ✅ FastLED вынесен из репозитория в `lib_deps` (3.4.0 → 3.5.0, собирается на всех трёх окружениях). EEManager и SimplePortal изменены в проекте, EncButton 1.x несовместим с новыми версиями - остаются в `libraries/`

## Этап 2. Веб-интерфейс на ESP
- ✅ Каркас: встроенный `ESP8266WebServer` + JSON API (вместо ESPAsyncWebServer + WebSocket, см. DECISIONS), страница gzip вшита в прошивку; управление питанием, яркостью, эффектами, таймером, лимитом тока — `docs/WEB_API.md`
- ✅ mDNS (`gyvertwink.local`); адрес по IP показывает приложение. QR-код не делаем: страница не может показать QR на саму себя, а адрес уже есть в приложении и README
- ⬜ Сцены/пресеты в LittleFS (конфиг + `effs[]`, около 80 байт на сцену)
- ⬜ Редактор координат: перетаскивание точек на canvas, подсветка выбранного светодиода
- ⬜ Калибровка по видео: запись штатной камерой → разбор кадров в браузере (обход ограничения HTTPS для камеры)
- ⬜ OTA-обновление прошивки по WiFi

1. Android-приложение остаётся; калибровка по видео в вебе — запасной вариант.
2. Приоритет после этапа 1 — веб-интерфейс (этап 2), новые эффекты идут мелкими PR между шагами.
3. Протокол только расширяется, совместимость со старым приложением сохраняется.
4. Нужны MQTT/Home Assistant и расписание по NTP (этап 3).
