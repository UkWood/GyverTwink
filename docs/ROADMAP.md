# Дорожная карта GyverTwink

**Статус документа: ЧЕРНОВИК — на обсуждении, не утверждён.**
Обновляется по мере работы. Статусы: ⬜ не начато · 🟡 в работе · ✅ готово · ❌ отклонено.

## Принципы
1. Сначала надёжность и проверяемость, потом новые функции.
2. Совместимость со старым Android-приложением сохраняется, пока не будет готова замена.
3. Каждый этап — отдельный PR с зелёным CI.

## Этап 0. Надёжность прошивки
- ✅ Валидация UDP-входа, защита от зависания `switchEff`, деления на ноль (PR #1)
- ✅ PlatformIO + CI-сборка (PR #1)
- ⬜ ACK на команды записи и повторы в приложении (теряются пакеты из-за 50-мс «антидребезга»)
- ⬜ Ограничение тока: `FastLED.setMaxPowerInMilliAmps()` (настройка в `cfg`)
- ⬜ Пароль точки AP по умолчанию → задаётся пользователем при первой настройке

## Этап 1. Тестируемость и репозиторий
- ⬜ Вынести логику протокола/выбора эффектов из `.ino` в `.h/.cpp` без привязки к железу
- ⬜ Юнит-тесты на хосте (PlatformIO `native`, Unity): граничные случаи из PR #1
- ⬜ Тестовый стенд протокола: скрипт на Python шлёт UDP-пакеты в хост-сборку логики
- ⬜ README: инструкция по сборке, прошивке, первому запуску и калибровке
- ⬜ Убрать вендорные библиотеки в `lib_deps` (обновить FastLED), APK — в GitHub Releases

## Этап 2. Веб-интерфейс на ESP
- ⬜ Каркас: `ESPAsyncWebServer` + WebSocket, страница (gzip) в LittleFS; управление питанием, яркостью, эффектами
- ⬜ mDNS (`gyvertwink.local`) и QR/адрес для открытия страницы
- ⬜ Сцены/пресеты в LittleFS (конфиг + `effs[]`, около 80 байт на сцену)
- ⬜ Редактор координат: перетаскивание точек на canvas, подсветка выбранного светодиода
- ⬜ Калибровка по видео: запись штатной камерой → разбор кадров в браузере (обход ограничения HTTPS для камеры)
- ⬜ OTA-обновление прошивки по WiFi

## Этап 3. Новые возможности

- ⬜ Расписание по NTP (вкл/выкл по времени, рассвет/закат)
- ⬜ MQTT / Home Assistant (автообнаружение)
- ⬜ Простая аутентификация (токен) для управления
