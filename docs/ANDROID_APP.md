# Приложение для Android («оболочка»)

Новое приложение (папка `android/`, Kotlin) — **тонкая оболочка вокруг веб-интерфейса гирлянды**. Весь интерфейс (управление, эффекты, сцены, расписание, карта, токен, калибровка по видео) — это страница, которую отдаёт сама прошивка. Поэтому любое изменение в `web/` попадает в приложение без пересборки APK, достаточно обновить прошивку. Старое приложение (Processing, `processing/`) остаётся рабочим, пока оболочка не догонит его по возможностям (калибровка живой камерой).

Решение владельца 2026-10-25: переходим с Processing на обычный Android-проект (Kotlin), начинаем с оболочки. Причины и сравнение вариантов — `docs/APP_UX.md` (этап C) и `docs/DECISIONS.md`.

## Что делает оболочка сама
| Часть | Где | Зачем |
|---|---|---|
| Экран подключения | `ConnectActivity` | поиск гирлянд по UDP (широковещательный пакет `{'G','T',0}`, порт 8888, ответ от самой гирлянды), ввод адреса вручную (IP или имя), кнопка точки доступа `192.168.4.1`; последняя гирлянда открывается сразу |
| Окно с веб-страницей | `WebActivity` | `WebView` с адресом гирлянды; переходы на чужие адреса открываются в браузере; повторить / другая гирлянда при ошибке сети; поворот экрана не перезагружает страницу; в фоне страница не опрашивает гирлянду |
| Камера для калибровки | `LiveCamera` + мост `GTApp.camera*` | живые кадры для вкладки «Калибровка» (в браузере карточка скрыта) |
| Выбор файлов | `WebActivity` | видео для калибровки, файл схемы «соты», прошивка (`<input type=file>` в WebView сам по себе не работает) |
| Окна `confirm()` / `alert()` | `WebActivity` | страница спрашивает подтверждение при удалении сцены, прошивке, снятии защиты |
| Чистая логика | `android/core` (без Android, тесты `gradle :core:test`) | пакеты протокола поиска, широковещательный адрес, проверка введённого адреса, «свой ли это хост» |

Токен доступа оболочка не хранит: страница спрашивает его сама и запоминает в `localStorage` своего адреса.

## Как сохранить то, что нужно только приложению
Страница знает про оболочку только по объекту `window.GTApp`. Его нет в браузере, поэтому страница работает как раньше. **Правило:** любая возможность, нужная только приложению, — это (1) метод в `GTApp` (в Kotlin: `WebActivity.Bridge`) и (2) блок в `web/`, который показывается только при `window.GTApp`. Никаких копий экранов в приложении.

Текущий мост (`GTApp`):
- `info()` — строка JSON `{"app":"android-shell","version":"…","host":"…"}`;
- `changeDevice()` — вернуться к экрану выбора гирлянды (в странице это кнопка «Сменить гирлянду» в шапке, видна только в приложении).

Камера для калибровки (`LiveCamera.kt`, Camera2 без внешних библиотек; разрешение `CAMERA` запрашивается при первом включении, камера нужна только там):
- `cameraStart()` / `cameraStop()` — включить (спросит разрешение) / выключить;
- `cameraStatus()` — JSON `{"state":"off|asking|starting|ready|error","message","w","h","rec","frames","ms"}` (`w`×`h` — размер кадров, `ms` — длина записи);
- `cameraLatest()` — последний кадр для показа: base64 яркости, `w*h` байт (пусто — кадров нет);
- `cameraRecord(on)` — начать / закончить запись кадров в память приложения (до 160 МБ, ~22 кадра в секунду);
- `cameraFrameAt(t)` — кадр записи, ближайший к моменту `t` (секунды от начала записи), тот же формат;
- `cameraClear()` — освободить память записи.

Как работает калибровка живой камерой: приложение только отдаёт кадры (серые, шириной 240 px, повёрнутые «прямо» по ориентации экрана; экран на время съёмки не гаснет и не поворачивается; автоэкспозиция и баланс белого фиксируются через секунду после включения). Всё остальное — на странице (`web/app.js`, блок «живая камера»): включает запись, запускает серию (`POST /api/vcalib/start`, пауза 2 с), ждёт её конца, останавливает запись и разбирает её той же функцией `analyzeVideo` (`web/calib.js`), что и видео из файла; кадры берёт из `cameraFrameAt`. Результат попадает в редактор координат как несохранённая правка. Поэтому алгоритм поиска светодиодов один и тот же для видео и камеры.

Планируется (отдельные PR): сохранение файлов (карта, экспорт).

## Как это переносится
| Что меняется | Что делать |
|---|---|
| Новый раздел / эффект / настройка в вебе | ничего в приложении: прошить гирлянду |
| Новая возможность, нужная только приложению | метод в `Bridge` + блок под `window.GTApp` в `web/` + проверка в `tests/web/ui_test.mjs` |
| Изменился поиск, адрес, ошибки сети | `android/` + тест в `android/core` |

## Сборка и проверка
- CI: задача `android` в `.github/workflows/build.yml` — `gradle :core:test :app:assembleRelease`, подписанный APK прикладывается как артефакт `gyvertwink-app` (ставится вручную с разрешением установки из неизвестных источников).
- Подпись: публичный ключ проекта `android/keystore/gyvertwink.jks` (причины и как заменить — `android/keystore/README.md`). Один ключ для debug и release, поэтому APK из CI и из релиза ставятся друг поверх друга.
- **Релиз:** поднять `versionCode` и `versionName` в `android/app/build.gradle.kts`, обновить `android/release-notes.md`, влить в `main`, затем запустить workflow `Release Android app` (Actions → Run workflow, ввести ту же версию). Он собирает подписанный APK, проверяет подпись, создаёт релиз `app-v<версия>` (старые релизы приложения названы так же) и прикладывает `GyverTwink-<версия>.apk`.
- Значок: `android/icon/gyvertwink-icon-512.png` (исходный), из него сделаны `mipmap-*/ic_launcher.png` и адаптивный значок (`mipmap-anydpi-v26`, фон `#000000`).
- Локально без Android SDK собирается и проверяется только `android/core`: `cd android && gradle :core:test`. Модуль `app` подключается, если задан `ANDROID_HOME` (или `-PwithApp`).
- Идентификатор приложения `ru.ukwood.gyvertwink` отличается от старого (`ru.alexgyver.GyverTwink`): приложения устанавливаются рядом.
- Gradle wrapper не хранится (бинарный jar): версия Gradle 8.14.3 указана в CI.
- Проверка на телефоне — `docs/HARDWARE_CHECKLIST.md`, раздел 8.

## Ограничения
- Страница отдаётся прошивкой: пока гирлянда не в сети, управлять нельзя (в старом приложении тоже). Экран подключения показывает причину.
- Страница по `http` без шифрования (в локальной сети шифрования нет и у прошивки); поэтому в манифесте разрешён открытый трафик.
- Для магазина приложение не готово (подпись публичным ключом, нет описания и скриншотов): только установка APK из Releases.
