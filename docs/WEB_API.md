# Веб-интерфейс и JSON API

Страница открывается по `http://gyvertwink.local` (mDNS) или по IP гирлянды (его показывает приложение в списке устройств).
Страница вшита в прошивку (gzip, около 6 КБ), интернет не нужен. Исходники — `web/`, сборка — `python3 tools/gen_web.py`
(результат — `firmware/GyverTwink_v1.2/web_page.h`, в репозитории лежит готовым; CI проверяет, что он соответствует исходникам).

## Правила
- Сервер — встроенный `ESP8266WebServer`, порт 80. Ответы JSON (`Cache-Control: no-store`), ошибки — `{"error":"<параметр>"}`.
- **Каждый POST обязан нести заголовок `X-Requested-With: GyverTwink`**, иначе `403 {"error":"forbidden"}`. Чужая страница в браузере
  не может отправить такой запрос без CORS-предзапроса, а устройство на него не отвечает: так сайт из интернета не управляет гирляндой в вашей сети (CSRF).
- Параметры — только неотрицательные целые, строго в диапазоне. Любое неверное значение даёт `400` с именем параметра, **ничего не применяется**.
- По умолчанию, как и UDP-протокол, API открыт для всех в локальной сети. Не выставляйте порт 80 гирлянды в интернет. Можно включить **защиту токеном** (раздел ниже).
- Параметры со знаком (`tz`, `lat`, `lon`, `onV`, `offV` у расписания) принимают ведущий `-`; остальные - только неотрицательные целые.

## Эндпоинты
| Запрос | Параметры | Ответ |
|---|---|---|
| `GET /` | — | страница (gzip) |
| `GET /api/state` | — | состояние (ниже) |
| `POST /api/set` | любые из: `ledAm` 1–1000 (`ledMax` в `/api/state`), `power` 0/1, `bright` 0–255, `auto` 0/1, `rnd` 0/1, `period` 1–255 (мин), `offOn` 0/1, `offMin` 1–250, `maxMa` 0–25500, `order` 0–5 (порядок цветов ленты: 0 RGB, 1 RBG, 2 GRB — по умолчанию, 3 GBR, 4 BRG, 5 BGR) | состояние |
| `POST /api/next` | — | состояние (после перехода на следующий эффект) |
| `GET /api/effect` | `n` 0–28 (22–27 — новые эффекты, 28 — «Огонь v2») | `{"n","fav","scale","speed"}`; у n=28 ещё `"shape","sparks","flicker"` (0–255) и `"cols"` — строка из 36 hex-символов: цвета шести уровней жара `rrggbb` от самого холодного к самому горячему |
| `POST /api/effect` | `n` и любые из `fav` 0/1, `scale` 0–255, `speed` 0–255, `show` 0/1; только для n=28: `reset` 1 (вернуть цвета уровней по умолчанию), `shape`, `sparks`, `flicker` 0–255 и цвет уровня жара — `lv` 0–5 вместе с любыми из `r`, `g`, `b` 0–255 (меняются только указанные каналы; цвет без `lv` — `400`; эти поля у других эффектов — `400`) | то же; `show=1` делает эффект текущим (`cur` в `/api/state`) сразу и надолго, без временного показа; при включённой автосмене её отсчёт начинается заново. Выбор в приложении по UDP по-прежнему показывает эффект 30 секунд |

### Защита токеном
Необязательная (вкладка «Прошивка», карточка «Защита доступа», `guard.ino`). Пока токен не задан, всё работает как раньше.

Когда токен задан, **все `/api/*` (и GET, и POST), кроме `GET /api/auth`, требуют заголовок `X-GT-Token: <токен>`**. Открыты только сама страница `GET /` и `GET /api/auth`. Загрузка прошивки `/update` токен не требует: её защищает физическое окно (3 нажатия кнопки), так что забытый токен не мешает обновиться.

| Запрос | Параметры | Ответ |
|---|---|---|
| `GET /api/auth` | заголовок `X-GT-Token` (необязателен) | `{"on","ok","locked","win","udpLock","min","max"}`: защита включена; токен из запроса подходит (или защиты нет); адрес заблокирован за подбор; окно обслуживания открыто; команды записи по UDP закрыты; допустимая длина токена |
| `POST /api/auth` | `token` — новый токен (8–32 символа: латиница, цифры, `. _ ~ -`; пустой — снять защиту) и/или `udpLock` 0/1 | то же состояние (`ok` = 1: запрос выполнен). Всё или ничего |

- **Задать, сменить и снять токен можно только при открытом окне обслуживания** (то же окно на 5 минут, что для обновления прошивки: три быстрых нажатия кнопки). Без окна `403 {"error":"window"}`. Старый токен для этого не нужен: забыл токен — открой окно и задай новый. После успешной смены окно закрывается. Поэтому никто из сети не может ни отобрать управление, ни заблокировать владельца; пока окно открыто, задать токен может любой в сети, поэтому делай это сразу.
- `udpLock` (закрыть/открыть команды записи по UDP) меняется **токеном, без окна** (а если защиты нет — свободно).
- Ответы: `401 {"error":"auth"}` — токена нет или он неверный; `429 {"error":"locked"}` (+ `Retry-After: 60`) — адрес заблокирован. Заголовок страницы проверяется раньше токена (`403`).
- **Подбор ограничен:** 5 неверных токенов подряд с одного адреса блокируют его на 60 секунд (и верный токен тоже не принимается). Запрос без токена подбором не считается; серия забывается после 10 минут тишины; таблица на 4 адреса, блокировки вытесняются в последнюю очередь.
- Сравнение токена - за время, не зависящее от места первого несовпадения. Токен хранится в EEPROM открытым текстом (физический доступ к плате и так даёт всё) и передаётся по HTTP без шифрования: это защита от случайных гостей сети, а не от того, кто слушает трафик.
- **UDP-протокол токена не знает**: приложение отправить его не может, а менять протокол можно только вместе с приложением (этап 4). По умолчанию UDP остаётся открытым. С `udpLock = 1` команды записи `{2,..}`, `{3,..}`, `{4,..}` отклоняются (при ACK - статус 3), запросы `{0}`, `{1}`, `{5}`, `{7}` отвечают как раньше. Без токена `udpLock` ни на что не влияет.

### Расписание и часы
Включение и выключение гирлянды по времени суток или относительно рассвета/заката (вкладка «Расписание», `schedule.ino`). Настройки лежат в отдельном блоке EEPROM (`Sched`, в конце).

| Запрос | Параметры | Ответ |
|---|---|---|
| `GET /api/schedule` | — | `{"en","tz","lat","lon","days","onT","onV","offT","offV","synced","src","utc","onAt","offAt"}` |
| `POST /api/schedule` | любые из: `en` 0/1, `tz` −720…840 (минуты от UTC), `lat` −9000…9000 и `lon` −18000…18000 (сотые доли градуса), `days` 0–127 (бит 0 — понедельник), `onT`/`offT` 0 — время суток, 1 — закат, 2 — рассвет, `onV`/`offV` — минуты суток 0–1439 (тип 0) или смещение −240…240 минут от заката/рассвета | то же, что GET; всё или ничего (`400 {"error":"<поле>"}`) |
| `POST /api/time` | `unix` — время UTC в секундах, от 1700000000 до 4102444800 | то же, что GET `/api/schedule` |

- `synced` — часы установлены; `src` — `none`, `ntp` (гирлянда подключена к роутеру) или `manual` (время прислала страница, пропадает при перезагрузке); `utc` — текущее время UTC (0, если не установлено).
- `onAt`/`offAt` — минуты суток, когда сегодня включится и выключится гирлянда (−1: расписание выключено, времени нет, день не выбран или солнце в этот день не восходит/не заходит).
- Событие срабатывает один раз в свою минуту, а не удерживает состояние: ручное включение/выключение действует до следующего события. После скачка времени (NTP, `POST /api/time`) пропущенные события не повторяются; при совпадении включения и выключения побеждает включение.
- Во время калибровки и записи прошивки события пропускаются. Рассвет и закат считаются по формулам NOAA (точность около минуты); смещение результата ограничено сутками.
- Часовой пояс постоянный (без перехода на летнее время): его меняют вручную. NTP работает только при подключении к роутеру; в режиме точки доступа время задаёт страница.

### Обновление прошивки по WiFi (OTA)
Загрузка `firmware.bin` из страницы (вкладка «Прошивка»). **Обновление возможно только пока открыто окно (5 минут), а открывает его физическое действие: три быстрых нажатия кнопки на гирлянде**
(лента мигает голубым). Так посторонний в сети WiFi не сможет прошить гирлянду, даже зная её адрес.

| Запрос | Параметры | Ответ |
|---|---|---|
| `GET /api/ota` | — | `{"open","left","free","busy"}`: окно открыто, секунд осталось, свободно под прошивку (байт), идёт запись |
| `POST /update` | `multipart/form-data` с файлом `firmware` | `{"ok":1}` и перезагрузка через 0,8 с; `403 ota-closed` (окно закрыто или нет заголовка страницы), `500 update` (файл отклонён) |

- Образ проверяет библиотека `Update`: первый байт `0xE9`, размер не больше свободного места; страница дополнительно проверяет файл до загрузки (0xE9, размер от 1 КБ до 1 МБ).
- Во время записи эффекты отключены. Успех закрывает окно: повторное обновление требует снова трёх нажатий.
- Плата перезагружается после ответа; страница ждёт возвращения гирлянды и показывает новую версию.
- Размер прошивки должен помещаться в раздел OTA (около 1 МБ на d1_mini): CI проверяет, что `firmware.bin` меньше 900 КБ.

### Калибровка по видео
Живая камера в браузере недоступна без HTTPS, поэтому калибровка идёт в два шага: гирлянда проигрывает серию, телефон снимает её штатной камерой, страница разбирает готовое видео.

| Запрос | Параметры | Ответ |
|---|---|---|
| `GET /api/vcalib` | — | состояние и параметры серии: `{"run","phase","e","i","n","delay","step","dark","flash","gap","end","marker","total"}` |
| `POST /api/vcalib/start` | `delay` 0–120 (с, по умолчанию 12), `step` 60–1000 (мс на светодиод, по умолчанию 120) | то же; `409 {"error":"busy"}`, если серия уже идёт |
| `POST /api/vcalib/stop` | — | то же; эффекты возвращаются |

Серия (время от старта): пауза `delay` с (включить запись) → `dark` мс темноты → **маркер** `flash` мс (горит до `marker` светодиодов равномерно по ленте — ток мал, лимит тока действует) →
`gap` мс темноты → светодиоды по одному, по `step` мс каждый, без промежутков → `end` мс темноты и возврат эффектов. Время считается по `millis()` от старта, не накапливается.

Разбор (`web/calib.js`, чистые функции, проверяются на синтетических кадрах):
1. Маркер ищется грубым шагом 0,1 с как пара «яркость выросла на всём кадре → через `flash` мс упала»; фронты уточняются шагом 20 мс. Из маркера по известным интервалам вычисляется момент каждого светодиода.
2. Светодиод `i` — самое яркое **появившееся** пятно в разности кадра в середине его слота и кадра предыдущего слота (погасший сосед и медленные изменения экспозиции не мешают); положение уточняется центром тяжести.
3. «Найден», если пятно заметно само по себе и по сравнению с типичным светодиодом ролика (движение людей даёт намного более слабые пятна). Ненайденные оцениваются линейно по соседям и помечаются в редакторе пунктирным кольцом.
4. Пиксели переводятся в карту прошивки: 60 клеток по ширине кадра, y в тех же клетках (как в приложении). Результат попадает в редактор координат как несохранённая правка.

Ошибки разбора понятны: маркер не найден, видео короче серии, найдено меньше 30% светодиодов, запись оборвалась раньше конца серии.
Рекомендации: телефон неподвижен, вся гирлянда в кадре, в комнате темно, запись начинается до первой вспышки.

### Координаты светодиодов (редактор)
Координаты — сетка 0–255 по x и y (как в приложении: один шаг сетки — клетка калибровки). Карта хранится в EEPROM (`xy[]`, `mm`).

| Запрос | Параметры | Ответ |
|---|---|---|
| `GET /api/xy` | — | `{"n","w","h","xy"}`: `xy` — hex, по 4 символа на светодиод (x, y); `w`,`h` — размер карты |
| `POST /api/xy?n=<число светодиодов>` | тело `text/plain`: hex ровно из `4*n` символов | `{"n","w","h"}`; границы пересчитываются и всё пишется в EEPROM |
| `POST /api/led` | `i` — зажечь светодиод `i` (с нуля), либо `off=1` — погасить и вернуть эффекты | `{}` |

- `n` в `POST /api/xy` защищает от гонки: если число светодиодов изменили (например, из приложения), пока страница правила точки, ответ `409 {"error":"count"}`, ничего не меняется.
  Неверная длина, не-hex символы — `400 {"error":"xy"}`. Запись «всё или ничего».
- Подсветка (`/api/led`) отключает эффекты; если страница закрылась, гирлянда сама вернётся к эффектам через минуту.
- Страница показывает точки на холсте, выбранный светодиод горит на гирлянде, точку можно перетащить или поправить числами. Красным кольцом помечены **подозрительные**
  точки (далеко от обоих соседей по ленте; длинный шаг между секциями гирлянды точку подозрительной не делает).

### Сцены
Сцена — набор настроек, который хранится в LittleFS (`/scenes.bin`, 8 мест) и применяется одним нажатием. В сцену входят **яркость, автосмена,
случайный порядок, период, текущий эффект и настройки эффектов 0–27**. Настройки «Огня v2» (28) хранятся отдельным блоком на гирлянде и в сцену не входят. Питание, число светодиодов и лимит тока — свойства установки, в сцену не входят и не меняются при её применении.

| Запрос | Параметры | Ответ |
|---|---|---|
| `GET /api/scenes` | — | `{"max":8,"scenes":[{"i":0,"name":"Вечер"},...]}` (только занятые места) |
| `POST /api/scenes/save` | `slot` 0–7, `name` | список сцен; имя: UTF-8, до 16 байт (обрезается по границе символа), без управляющих символов; кавычки и `\` заменяются на `'` |
| `POST /api/scenes/load` | `slot` | состояние (как `/api/state`); `404 {"error":"empty"}`, если место пусто |
| `POST /api/scenes/delete` | `slot` | список сцен; `404`, если место пусто |

Файл защищён версией и контрольной суммой: любое несоответствие (порча, другой размер, недопустимые значения) — сцен нет, прошивка не падает.
Запись идёт через временный файл (`/scenes.tmp` → переименование), при ошибке записи (`500 {"error":"fs"}`) в памяти и на диске остаётся прежнее содержимое.

Состояние: `{"fw","ledAm","ledMax","power","bright","auto","rnd","period","offOn","offMin","maxMa","cur","count","heap"}`,
где `cur` — номер текущего эффекта, `count` — число эффектов, `heap` — свободная память.

Любое изменение через `POST /api/set` и `/api/next` останавливает принудительный показ эффекта — так же, как команды `{2,...}` по UDP.
Логика изменения настроек общая с UDP (`settings.ino`), поведение обоих способов проверяется тестами.

## Тесты
- `make -C tests` — обработчики `web.ino` вызываются без сети (`tests/test_web_cases.h`).
- `node tests/web/ui_test.mjs ./tests/gt_host` — страница в настоящем Chromium против настоящего кода прошивки (`make -C tests gt_host`).
