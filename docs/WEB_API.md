# Веб-интерфейс и JSON API

Страница открывается по `http://gyvertwink.local` (mDNS) или по IP гирлянды (его показывает приложение в списке устройств).
Страница вшита в прошивку (gzip, около 6 КБ), интернет не нужен. Исходники — `web/`, сборка — `python3 tools/gen_web.py`
(результат — `firmware/GyverTwink_v1.2/web_page.h`, в репозитории лежит готовым; CI проверяет, что он соответствует исходникам).

## Правила
- Сервер — встроенный `ESP8266WebServer`, порт 80. Ответы JSON (`Cache-Control: no-store`), ошибки — `{"error":"<параметр>"}`.
- **Каждый POST обязан нести заголовок `X-Requested-With: GyverTwink`**, иначе `403 {"error":"forbidden"}`. Чужая страница в браузере
  не может отправить такой запрос без CORS-предзапроса, а устройство на него не отвечает: так сайт из интернета не управляет гирляндой в вашей сети (CSRF).
- Параметры — только неотрицательные целые, строго в диапазоне. Любое неверное значение даёт `400` с именем параметра, **ничего не применяется**.
- Как и UDP-протокол, API открыт для всех в локальной сети (без пароля). Не выставляйте порт 80 гирлянды в интернет.

## Эндпоинты
| Запрос | Параметры | Ответ |
|---|---|---|
| `GET /` | — | страница (gzip) |
| `GET /api/state` | — | состояние (ниже) |
| `POST /api/set` | любые из: `ledAm` 1–500, `power` 0/1, `bright` 0–255, `auto` 0/1, `rnd` 0/1, `period` 1–255 (мин), `offOn` 0/1, `offMin` 1–250, `maxMa` 0–25500 | состояние |
| `POST /api/next` | — | состояние (после перехода на следующий эффект) |
| `GET /api/effect` | `n` 0–21 | `{"n","fav","scale","speed"}` |
| `POST /api/effect` | `n` и любые из `fav` 0/1, `scale` 0–255, `speed` 0–255, `show` 0/1 | то же; `show=1` показывает эффект 30 секунд (как выбор в приложении) |

### Координаты светодиодов (редактор)
Координаты — сетка 0–255 по x и y (как в приложении: один шаг сетки — клетка калибровки). Карта хранится в EEPROM (`xy[]`, `mm`).

| Запрос | Параметры | Ответ |
|---|---|---|
| `GET /api/xy` | — | `{"n","w","h","xy"}`: `xy` — hex, по 4 символа на светодиод (x, y); `w`,`h` — размер карты |
| `POST /api/xy?n=<число светодиодов>` | тело `text/plain`: hex ровно из `4*n` символов | `{"n","w","h"}`; границы пересчитываются и всё пишется в EEPROM |
| `POST /api/led` | `i` — зажечь светодиод `i` (с нуля), либо `off=1` — погасить и вернуть эффекты | `{}` |

- `n` в `POST /api/xy` защищает от гонки: если число светодиодов изменили (например, из приложения), пока страница правила точки, ответ `409 {"error":"count"}`, ничего не меняется.
  Неверная длина, не-hex символы — `400 {"error":"xy"}`. Запись «всё или ничего».
- Подсветка (`/api/led`) отключает эффекты; если страница закрылась, гирлянда сама вернётся к эффектам через минуту.
- Страница показывает точки на холсте, выбранный светодиод горит на гирлянде, точку можно перетащить или поправить числами. Красным кольцом помечены **подозрительные**
  точки (далеко от обоих соседей по ленте; длинный шаг между секциями гирлянды точку подозрительной не делает).

### Сцены
Сцена — набор настроек, который хранится в LittleFS (`/scenes.bin`, 8 мест) и применяется одним нажатием. В сцену входят **яркость, автосмена,
случайный порядок, период, текущий эффект и настройки всех 22 эффектов**. Питание, число светодиодов и лимит тока — свойства установки, в сцену не входят и не меняются при её применении.

| Запрос | Параметры | Ответ |
|---|---|---|
| `GET /api/scenes` | — | `{"max":8,"scenes":[{"i":0,"name":"Вечер"},...]}` (только занятые места) |
| `POST /api/scenes/save` | `slot` 0–7, `name` | список сцен; имя: UTF-8, до 16 байт (обрезается по границе символа), без управляющих символов; кавычки и `\` заменяются на `'` |
| `POST /api/scenes/load` | `slot` | состояние (как `/api/state`); `404 {"error":"empty"}`, если место пусто |
| `POST /api/scenes/delete` | `slot` | список сцен; `404`, если место пусто |

Файл защищён версией и контрольной суммой: любое несоответствие (порча, другой размер, недопустимые значения) — сцен нет, прошивка не падает.
Запись идёт через временный файл (`/scenes.tmp` → переименование), при ошибке записи (`500 {"error":"fs"}`) в памяти и на диске остаётся прежнее содержимое.

Состояние: `{"fw","ledAm","ledMax","power","bright","auto","rnd","period","offOn","offMin","maxMa","cur","count","heap"}`,
где `cur` — номер текущего эффекта, `count` — число эффектов, `heap` — свободная память.

Любое изменение через `POST /api/set` и `/api/next` останавливает принудительный показ эффекта — так же, как команды `{2,...}` по UDP.
Логика изменения настроек общая с UDP (`settings.ino`), поведение обоих способов проверяется тестами.

## Тесты
- `make -C tests` — обработчики `web.ino` вызываются без сети (`tests/test_web_cases.h`).
- `node tests/web/ui_test.mjs ./tests/gt_host` — страница в настоящем Chromium против настоящего кода прошивки (`make -C tests gt_host`).
